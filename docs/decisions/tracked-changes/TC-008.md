No existing tracked change covered the visual direction, so this is a new record rather
than a duplicate of one. D41 (typography) and TC-007 (the font files) stand unchanged.

## What was built

**Artwork — 19 real SVG assets** in `frontend/svg/decor/`, copied to the static root by
`bun run build:assets` and referenced from CSS backgrounds: paper texture, sun with
separate rays, two leaf sprigs, a plant, two grass strips, stones, a puddle, the two
handwritten margin notes with their underlines, the taped pale paper note, the wooden
LOOK / EXPLORE / WIGGLE signpost, and six activity illustrations.

They are **assets, not logic**: every one is a background on an empty `aria-hidden`
span, so none enters the accessibility tree, takes focus, intercepts a click or can be
selected, and the whole layer disappears in print and under forced colours. The board is
**not** used as a page background or a screenshot — the text, form, buttons and cards
are real responsive HTML.

**Interface.** Masthead with the brand and a leaf sprig, then the board's heading "A
little fresh air?"; compact question groups; tiles with the control, icon and label on
one row and a sage fill with a dark green border when selected; ages and time four
across, energy three, who two; the town field and the location button on one row; plain
checkbox rows above a thin divider; a full-width dark green submit button with an arrow;
the weather strip and answers summary as soft bands rather than outlined panels; pastel
cards with one practical fact per row, each with its own icon, and an underlined link.

**Responsive, deliberately.** Desktop fills the margins. Phone keeps a named subset —
sun, sprig, taped note, bottom grasses — in a reserved band above the masthead and along
the bottom edge, so nothing overlaps a word; the signpost and the two lettered margin
notes are omitted because there is no margin to put them in. The composition is never
scaled down as a whole.

## A security finding this surfaced

A browser refuses the `__Host-` session cookie (D31) over plain HTTP, and the local
origin policy only allowed `http://` origins — so **neither scheme worked in a real
browser locally**: HTTP lost the cookie, HTTPS was refused by the origin check. Over
curl it looked fine, which is why no test caught it. `origin_policy` now accepts both
schemes on the local names in development only; hosted mode stays https-only and a new
test asserts it never allows a plain-http origin.

## Second pass (the defects Mats found in the error page screenshot)

- **The 422 re-render was never broken, but reaching it was.** A browser could not submit
  the form at all, so every POST became 403 SESSION_INVALID and showed the separate
  "Return to the form" page. Two accepted rules were to blame, both fixed:
  - **`__Host-` + `Secure` over plain HTTP.** A browser discards that cookie on an
    insecure origin, so the session never persisted. Development now uses `wo_session`
    without `Secure`; **the hosted product keeps `__Host-wo_session` + `Secure` exactly**,
    with a test for each.
  - **`Referrer-Policy: no-referrer` (PLAN §9) makes Chromium send `Origin: null` on a
    form POST**, and BACKEND-CONTRACT §5 refuses a null Origin with 403. Those two rules
    together meant **no submission could ever succeed, in the hosted product as much as
    locally** — this was a release blocker, not a local annoyance. PLAN §9 now specifies
    `Referrer-Policy: same-origin`, which still sends nothing cross-origin. A regression
    test pins the header and asserts a POST is accepted.
  - I had earlier blamed the self-signed certificate for `Origin: null`. That was wrong;
    it was `no-referrer` all along, and the browser journey works over both schemes now.
- **Every page is one cream panel**: the results and error pages are wrapped, a nested
  panel (the plan form inside "Change answers") is neutralised, and the column is
  `--wo-panel-w` = 480 px.
- **Decorations are anchored to the panel, not the window.** `--wo-side` is the width of
  one margin, so each piece keeps its place beside the panel at any width, and the
  vertical positions run top to bottom so the margins are filled.
- **Scale**: sun 160 px against a 480 px panel (a third of its width); signpost 316 px;
  the handwritten notes are 220–230 px wide.
- **Checked programmatically at 320, 390 and 1440**: no clipped label, no decoration
  off-canvas, and no lettered decoration overlapping another. The only remaining overlap
  is the signpost standing on the grass, which is how the board draws it.

## Open items

- **Fixture data is not labelled as an example in the UI.** The brief requires it; the
  cards currently present `PreviewPlanner`'s places and weather as if real. Needs a
  notice, and it is a product-copy decision.
- **The handwritten notes are set in Switzer, not a handwriting face.** No handwriting
  font is licensed. The tracking, rotation and drawn underline give a pinned-note
  character, but it is not the board's marker hand and is not claimed to be.
- No illustrated people or children, per the standing exception; the surrounding nature
  detail in that area is kept.
- axe, the contrast script and the CSP journeys have not run (WP9b).
