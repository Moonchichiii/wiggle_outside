# TC-004 — `scripts/check.ps1` and `release.ps1` are the gate scripts

| Field | Value |
|---|---|
| Change | `scripts/check.sh` and `release.sh` become `scripts/check.ps1` and `release.ps1`. The `.sh` names are removed from the specification; they are not kept as an alternative. |
| Reason | The build runs on Windows 11 with PowerShell 7. A POSIX sh gate script would need Git Bash locally, where CRLF, path and shim differences make "green locally" less trustworthy than real Linux CI — or a second script for CI, which is a second gate list that can drift. |

## One gate script, local and CI

CI runs on GitHub's Linux runners and invokes the same `./scripts/check.ps1` with
`shell: pwsh`, which `ubuntu-latest` has preinstalled. That is the point of the change:
one file, two platforms, no second list of gates.

It only holds if the script stays portable, so PLAN §8 now records the constraints: no
drive letters or backslash path literals, `Join-Path` for paths, tools invoked through
`uv run` and `bun run` rather than absolute paths, and a non-zero exit from any tool fails
the job. A policy test asserts that every workflow's gate step calls
`./scripts/check.ps1` and that no workflow inlines a gate command of its own.
