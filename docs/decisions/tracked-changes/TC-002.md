## Resolution

The short-circuit **stays**. Dropping it would need a multi-reason precedence rule that
exists nowhere and would contradict BACKEND-CONTRACT §1, CONTRACTS §3 and BUILD-PACKAGES
WP6. Instead the copy stops making a claim, and the remedy path — "Change answers" — is
documented as re-running everything.

**Approved copy for DAYLIGHT_TOO_SHORT:**

> **Not enough daylight for this one.** The outing would end after sunset. Change your
> answers and we'll check the daylight and the weather again, or leave the adventure for
> tomorrow.

DAYLIGHT_NIGHT is unchanged: it names no remedy.

## Scope of (b)

Applies to the fresh-key "Change answers" path (CONTRACTS §7). **Unchanged:**

- the lost-response join — same key, same fingerprint, returns the same job (CONTRACTS §7);
- a repeated POST for the same owned location candidate (BACKEND-CONTRACT §3).

D43 is **not** reopened. These return an existing job rather than resubmitting answers.

## Consequence now stated explicitly

`planned_start` is the job's admission time (BACKEND-CONTRACT §1), so a resubmission
shifts the outing window. The same answers sent a few minutes later can therefore cross
into DAYLIGHT_TOO_SHORT, or out of it, with nothing edited. That is intended, and it is
why the copy promises a re-check rather than an outcome.
