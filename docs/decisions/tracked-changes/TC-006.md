# TC-006 — M0 time-boxed to five gates; WP9b carries the rest, in parallel

| Field | Value |
|---|---|
| Change | M0's gate set is reduced to **ruff, mypy, import-linter, pytest and the contract tests**, plus one CI workflow with the `check` job and `gates.lock`. WP9 splits: **WP9a** is in M0, **WP9b** holds everything else and runs **in parallel with WP1–WP8**. |
| Reason | M0 is time-boxed to about 90 minutes so the package work can start the same evening. The full PLAN §8 gate set cannot be built and proved in that window, and several of its gates (Bun/Tailwind build, frontend linters, coverage thresholds) have nothing to act on until WP8 exists. |

## Why this is a tracked change and not a quiet reduction

PLAN §8 and BUILD-PACKAGES §2 both say a gate is never weakened, and AGENT-BRIEF repeats
it. Reducing the initial set without a record would be exactly that. This record makes it
a scheduling decision with a named owner, a named end state and a standing restriction.

## In M0 (WP9a)

- `scripts/check.ps1` running ruff (format + lint), mypy, import-linter, pytest and the
  contract tests.
- `ruff.toml`, `mypy.ini`, `pytest.ini`, `.importlinter`.
- One workflow with the `check` job, on `pull_request`, no secrets.
- `gates.lock` over the BUILD-PACKAGES §2.1 protected inputs; Mats signs the commit.

## Deferred to WP9b (parallel with WP1–WP8)

| Deferred | Consequence while deferred |
|---|---|
| `supply-chain.yml` and the canonical audit (ARCHITECTURE §13.3) | **No vulnerability scanning.** D19 (block on any known vulnerability) is not enforced. Nothing may be released or deployed, and no supply-chain claim may be made. |
| `dependency-review.yml`, `security.yml` (CodeQL, gitleaks, zizmor) | No automated secret, workflow or code scanning on PRs. |
| Seeded-violation proofs (each gate fails on a planted fault) | The five M0 gates are green but **not yet proved to fail**, so "the gates work" is unproven until WP9b. |
| Bun/Tailwind production build, djLint, Biome, Stylelint, contrast script | No frontend gate. WP8 output is unchecked by CI until WP9b. |
| `tests/policy/**` (SHA-pinned actions, no inline script/style, source and dependency budgets) | The ≤ 8 runtime dependency budget and the no-inline-style rule are documented but unenforced. |
| Coverage thresholds (`core` 100 / `planner` 95 / total 90) | Coverage is not measured. |
| `gate-integrity` | A PR can change a protected input without failing a check. Mats's signature on `gates.lock` is the only control until WP9b. |
| `browser.yml` (Playwright under CSP, axe, Lighthouse) | Already dependent on WP8; unchanged by this TC. |

## Standing restriction

Until WP9b is green: **nothing is released, deployed or described as supply-chain
verified, and no gate coverage is claimed beyond the five gates in WP9a.** Any evidence
file written before then says which gates ran.
