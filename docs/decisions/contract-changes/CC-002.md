# CC-002 — `Activity` is missing six catalogue fields

| Field | Value |
|---|---|
| Raised by | WP1 (core rules), in its hand-off report |
| Change | `Activity` gains `who`, `rain_ok`, `max_rain_pct`, `max_temp_c`, `seasons`, and `minutes_min`/`minutes_max` replacing the single `duration_min`. `Season` moves into `core/types.py`. |
| Status | **accepted** by the integration owner |

## Why

`docs/drafts/activities.toml` — the catalogue Mats reviewed (D14) — sets `who`,
`minutes = [min, max]`, `rain_ok`, `max_rain_pct`, `max_temp_c` (optional), `seasons` and
`places` on every entry. `Activity` carried none of the first six.

The root cause is a documentation defect I then copied: CONTRACTS §2 said only
"catalogue fields as in drafts/activities.toml", and the type was written from that
sentence instead of from the file. §2 now lists every field explicitly, and a contract
test parses the TOML and compares the key set, so prose cannot stand in for the shape
again.

## Consequences this unblocks

- `is_eligible` took `limits: WeatherLimits` and `seasons: frozenset[Season]` as
  parameters because the entry could not carry them. It can now read the entry.
- `selected_duration` was implemented and tested as a formula, but `pair_candidates`
  could only put `activity.duration_min` into `Pair.duration_min`, so the
  clamp(budget − travel, min, max) never applied end to end. With the range present it
  does.
- Solo/kids separation was inferred from `ages` being empty. `who` now states it, which is
  how the catalogue encodes it.

## Packages affected

- **WP1** rebases: read the limits and seasons from the entry, use `minutes_min` for the
  fits-time rule and the clamp.
- **WP2** (catalogue loader) was blocked by this; it can now map every TOML key to a field.
- **WP6** builds pairs from `Activity` and gets the correct duration.

## Tests that change

WP1's fixtures gain the new fields; its fits-time and duration tests use the range.
New: `tests/contract/test_catalogue_shape.py`.
