# CC-003 — `Hook` cannot express the rules PLAN §3 states

| Field | Value |
|---|---|
| Raised by | WP1 (core rules), in its hand-off report |
| Change | `Hook` gains `for_who` (TOML `for`), `needs_destination` and `generic_only`. `Reason.when` is documented as reviewer-facing prose, not a machine-evaluated expression. |
| Status | **accepted** by the integration owner; one open item for Mats |

## Why

`docs/drafts/hooks.toml` documents three gating keys in its header and sets them on every
hook:

- `needs_destination`: the sentence assumes a destination, so it is offered only when the
  pair has one.
- `generic_only`: offered only for generic pairs with an absent destination.
- `max_energy`: offered only when the activity's top energy level is at or below this.

`Hook` carried `hook_id`, `text` and `max_energy` — so two of the three rules, and the
`for` audience, could not be represented. Without them nothing can derive a pair's
`allowed_hook_ids`, which blocks `core/ideas.py` and WP6.

## `Reason.when`

`when` is prose describing the condition ("straight-line distance is 1 km or less"). There
is no vocabulary and it is not evaluated. The conditions are implemented in
`core/ideas.py`, keyed by `reason_id`. Stated in CONTRACTS §2 so no package tries to parse
it.

## Open item for Mats

PLAN §3 also mentions `places = ["any"]` semantics for hooks. `hooks.toml` has no `places`
key — the audience key is `for`. Either PLAN §3 is stale here or a key is missing from the
catalogue. Not blocking: `for_who`, `needs_destination` and `generic_only` cover every rule
the current hooks express. Flagged for review alongside the catalogue.

## Packages affected

- **WP1 / whoever writes `core/ideas.py`**: can now derive `allowed_hook_ids` per pair.
- **WP2** (loader) maps the three keys.
- **WP6** supplies the derived sets to the model request.

New: the hook-flag assertions in `tests/contract/test_catalogue_shape.py`.
