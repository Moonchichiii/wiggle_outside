# CC-001 — `WeatherWindow` is missing the hourly precipitation (mm) array

| Field | Value |
|---|---|
| Raised by | WP1 (core rules), in its hand-off report |
| Change | Add `precipitation_mm: tuple[float, ...]` to `WeatherWindow` (`core/types.py`). |
| Status | **accepted** by the integration owner |

## Why

BACKEND-CONTRACT §1 lists `precipitation` among the hourly variables the adapter
requests, and two rules depend on millimetres, not probability:

- `rain_ok = false`: every precipitation interval has probability ≤ `max_rain_pct`
  **and 0 mm**.
- Reason `dry_window`: every interval has probability ≤ 20 % **and 0 mm**.

`WeatherWindow` carried `precip_probability` only, so neither rule was expressible. This
is a WP0 omission, not a new decision: CONTRACTS §2 already said "hourly arrays as
received (BACKEND-CONTRACT §1)" — the type simply did not match the sentence.

## Packages affected

- **WP1** wrote `used_samples(window, outing, precipitation_mm)` with the array as a third
  parameter as a documented workaround. It now reads `window.precipitation_mm`, which also
  removes the chance of passing precipitation from a different forecast.
- **WP3** (`integrations/open_meteo.py`) must populate the field, and its recorded fixture
  `tests/fixtures/providers/open_meteo_boundary.json` must include the array.
- **WP4** caches `WeatherWindow` via `to_cache`/`from_cache`, so the array travels with it.

## Tests that change

WP1's weather tests drop the third argument. A new contract test asserts the field exists
(`tests/contract/test_catalogue_shape.py` covers `Activity`/`Hook`; the `WeatherWindow`
field is asserted through WP1's interval tests and the CONTRACTS §2 row).
